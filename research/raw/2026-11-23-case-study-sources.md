# Raw notes: case study and blog sources (read 23 Nov 2026)

- saranzafar.vercel.app (Apr 2026): template Problem (1 specific para) / Constraints (3-4 real) / Decisions table Picked-Rejected-Why / Outcome (1 headline number + 2 supporting + 1 qualitative) / What I'd do differently. 500 words = tweet, ~1,200 sweet spot, 2,500 only if complex, 5,000 nobody reads. Numbers are falsifiable; vague = marketing. Excalidraw diagram or real screenshot as cover.
- GreatFrontEnd portfolio (Jun 2026): Problem, Context, My role, Frontend decisions (state, data fetching, boundaries, routing, a11y, perf, testing), Trade-offs (what not chosen), Quality, Result, Next. 2-4 case studies + notes + code samples; best case study above bio. Show constraints, trade-offs, bugs, follow-up work; no perfect narratives; no invented impact; say what changed concretely. Demo needs README with setup, decisions, limitations. Architecture note: server vs client state, URL state, form state, partial API failure.
- SlateGit trade-offs (Jun 2026): every big choice gets "why this, not that" in 1-3 sentences naming the constraint and what would change the answer. 3-5 decisions, 2-4 sentences each. Keep decision.md while building. Skip trivial choices.
- SlateGit blog as hiring signal: 800-1,500 words; post types that work: bug postmortem, approach comparison, design decision walkthrough, OSS notes, retrospective. Avoid doc rehash, hiding dead ends, publishing once. Own domain, link GitHub + LinkedIn.
- AlgoMaster (Jun 2026): teach from experience; open with problem; include real artifact (error, query plan, before/after, diagram, code). 800-1,500 words, split over 2,000. Publish on own domain, dev.to, Hashnode, Medium (paywall); canonical when cross-posting. Specific titles ("cut p99 800ms to 120ms").
- dev.to Rizwan Saleem: seniority = ownership, cross-functional impact, risk awareness, people impact. Impact ledger (context, action, impact, lessons). 2-3 case studies with before/after, mentoring evidence, runbooks, diagrams.
- Manning "Writing for Developers" ch.10: "How we built it" pattern (only headings readable).
